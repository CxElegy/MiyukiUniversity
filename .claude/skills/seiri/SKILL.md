# 受験の情報整理

情報は多いほど迷う。**「美幸が今、何をすればいいか」がすぐわかる**ことを一番にして、
入ってきた情報を `juken.yaml` のどこかに振り分けるか、捨てる。

## 1. 振り分け（どこに入れるか）

| 情報の種類 | 入れる先 | 例 |
|---|---|---|
| 日付が決まっている公式の予定 | `schedule`（全員に関係）／`targets[].dates`（その大学だけ）| 共テの受験票、国公立の出願期間 |
| 美幸がやること | 今の期間なら `plan` の `todo`、いつでもいいなら `checklist` | 調査書を頼む、写真を撮る |
| 制度の変更・注意 | `changes`（**最大8件**。古くなったら消す）| 受験票の取得方法が変わった |
| 大学の候補 | `recommend`（`daigaku` スキルで調べてから）| 新設学部 |
| 参考になるサイト | `links` | 公式の特設ページ |
| ニュースの集め方 | `topics`（`queries` / `match` / `exclude` / `urgent`）| いらない記事が混ざる |
| どれでもない・美幸に関係ない | **捨てる**（会話で「入れなかったもの」として一言伝える）| 他県の高校入試、医学部の話 |

## 2. 入れる前のチェック

1. **本人に関係ある？** 理系・地方国公立・共テ利用・東洋/MARCH の押さえ、のどれかに関係なければ入れない。
2. **確かな情報？** 公式の発表か。日付・数字には `source`。うわさは入れない。暫定は `tentative: true`。
3. **やることがある？** 行動が必要なら、締切の何日前に何をするかまで `todo` に書く（「〜を確認」より「〜に電話して〜を聞く」）。
4. **重なってない？** 同じ日程・同じ注意がもうないか `grep` で探す。あれば直す、増やさない。
5. **身元が分からない？** 学校名・クラス・フルネーム・住所・顔写真は書かない。ニュースに混ざったら `exclude` で止める。

## 3. 見やすさのルール（ページの構成）

- ページ上部は「いまやること」と「次の締切 5件」だけ。ここに出るのは
  `plan` の今の期間と、`schedule`/`targets` の近い日程。**上に出したい＝日程か今の todo に入れる**。
- それ以外は4つのタブ（スケジュール／大学えらび／ニュース／本番の準備）。
- `plan` の 1 期間の `todo` は **6個まで**。増えたら優先度の低いものを `checklist` へ。
- 日程の `title` は「何が・いつまで」が分かる 30 字以内、カレンダー用の `short` は 8 字くらい。
- 過ぎた日程は消さない（カレンダー・ガントチャートで薄く表示される）。

## 4. 今週のまとめ（頼まれたら）

会話で短く返す（ページは変えない）：

- **今週の締切**（日付・何をするか）
- **来週までにやること**（`plan` の今の期間の todo から、まだのもの）
- **新しく分かったこと**（この1週間の `state/news.json` から、美幸に関係あるものだけ 3 件まで）
- **気になること**（日程の重なり、入学金の締切が国公立の発表より前、など）

## 5. 終わったら

`python scripts/juken.py render` → `python -m unittest discover tests` →
スクリーンショットで上部とタブを確認 → commit・push。
何を入れて何を捨てたかを、会話で箇条書き3〜5行で伝える。
